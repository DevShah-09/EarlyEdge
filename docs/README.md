# EarlyEdge Engineering Documentation

This documentation describes the repository as implemented. It covers the product features, frontend and backend flows, machine-learning choices, formulas, persistence, environment variables, integrations, and known limitations.

EarlyEdge is a React/FastAPI/Supabase application for screening and operational follow-up of three non-communicable disease (NCD) risks:

- diabetes;
- hypertension;
- cardiovascular disease (CVD).

> Clinical status: this repository is a prototype decision-support system. Its models were trained on synthetic data generated by this repository, are not clinically validated, and must not be treated as diagnostic devices.

## Main end-to-end flow

1. A hospital user signs in with Supabase Auth.
2. The browser uploads CSV/XLS/XLSX patient data to FastAPI.
3. The backend normalizes and preprocesses values, loads serialized classifiers, and generates three disease probabilities.
4. It computes a composite risk score and tier, attempts SHAP explanations, and upserts patients plus risk-history snapshots into Supabase.
5. The dashboard, patient directory, planning tools, and task workflows read those records through FastAPI.
6. A clinician can generate an LLM or template-based 30-day care plan, approve it, and dispatch it through SMTP (or a mock mode).
7. High-risk patients can be assigned to ASHA workers; ward aggregates drive screening-camp recommendations.

## Source-of-truth convention

When comments, README claims, UI labels, and executable code disagree, these docs describe executable code as the current behavior and call out the discrepancy. The most important example is model selection: comments say “best by recall,” but `backend/ml/trainer.py` actually picks the largest test accuracy.
